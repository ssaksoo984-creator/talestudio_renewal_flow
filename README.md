# Tale Studio 리뉴얼 플로우

리뉴얼(축소) 사용자 플로우와 화면 목업. 플로우차트와 목업이 같은 노드 ID를 쓴다.

- `index.html` — **프로토타입 (메인)**. 목업이 실제로 동작한다(입력·선택·생성 결과가 다음 화면까지 이어짐). 넓은 화면에서는 오른쪽에 플로우가 붙어 있고, 지금 화면이 빨간 그라데이션 테두리로 표시된다. 노드를 누르면 그 화면으로 이동한다. `index.html#A5`처럼 노드 ID로 바로 열 수 있다. 프로토타입 페이지라 `<!doctype>`/`<head>` 없이 쓰고, 게시할 때 감싸진다.
- `flow.html` — 플로우 문서. 단계별 플로우차트 + 노드 설명 + 검토 메모 + 작은 목업.
- `src/flow.js` — 플로우 데이터 (단계, 원칙, 노드, 엣지, 결정할 것, 오류 번호). **플로우를 바꿀 때는 여기만 고친다.**
- `src/screens.js` — 노드 ID별 화면 목업과 목업 상태·동작.
- `src/flowview.js` — 두 페이지가 함께 쓰는 플로우차트 그리기와 현재 노드 표시.
- `src/base.css` — 두 페이지가 함께 쓰는 색 토큰과 와이어프레임 스타일.
- `reference/` — 2026-10-13 인수인계 자료 원본.

## 노드 종류

| type | 뜻 |
|---|---|
| screen | 화면 |
| modal | 팝업 · 확인창 |
| decision | 예/아니오 · 갈림 |
| ai | AI 작업 중 — 화면 전체 잠금 |
| error | 오류 안내 (⚠) |
| ext | 이번 범위 밖 (Director → Editor) |

엣지 kind: `yes` · `no` · `back`(롤백, 빨간 점선).

## 이번 기준 (2026-10-13)

Producer(① 이야기 재료 → ② 설정: 장르·분위기 · 길이 · 바꿈 정도 · 화면 비율 🔒) → Writer(산문 작업공간) → 브레이크다운 → Artist(목록 → 스타일 🔒 → 생성 · 객체별 톤) → Storyboard(가칭, v18 Writer의 러프 스토리보드) → Director → Editor.
인물·배경을 늘리려면 산문으로 롤백. 인물 모습(상태)은 Artist 카드나 Storyboard 샷 편집에서 롤백 없이 추가.

## Artist 카드 (v18 그룹 카드 참고)

인물·배경마다 한 묶음 카드. 첫 모습이 크게, 나머지 모습은 오른쪽에 "└ 민호의 모습 N"으로 작게, 끝에 [＋ 모습 추가]. 모습이 있으면 카드가 한 줄을 다 쓴다. 칸을 누르면 그 모습으로 상세(A7)가 열린다. 배경은 16:10, 모습 없음.

## 상세 팝업 (v18 상세 참고)

왼쪽 큰 그림(모습 이름 · 기준 표시 · 기록 아이콘 · [↻ 다시 만들기]), 오른쪽 역할 · 설명(기준 / 이 모습, ✎ 고치면 "바뀜" 표시) · 레퍼런스 · 모습 목록([보기] [삭제] · [＋ 모습 추가하기] → 추가만 / 추가하고 생성) · 쓰인 샷(→ 샷 고치러 가기). [↻ 다시 만들기]는 설명 · 캐릭터성 추천(접힘) · 바꾸고 싶은 곳(전체 새로 / 얼굴 · 머리 / 의상 / 표정 · 자세 / 색감 · 분위기) · 기준으로 쓸 이미지 · 생성 도구를 정한다(A7r). Artist는 Storyboard로 넘어가도 잠기지 않는다(목록만 산문을 따름). Storyboard 샷 편집의 모습 ▾ [＋ 새 모습…]도 이 상세 팝업을 그대로 연다.

## Storyboard (v18 Writer 흐름을 Artist 뒤로)

- S0 씬·샷 나누고 러프 그리기(진행 단계 표시, 잠김)
- S1 씬마다 묶인 샷 카드(시작 · 연출 러프 그림 · 지문 @인물 · 첫 대사 · 크기/앵글/무브먼트), [러프 | 대본] 보기. 러닝타임은 목표가 아니라 지표라 제목 옆에 "씬 · 샷 · 초"만 작게 (목표는 산문 분량을 정할 때만 씀)
- S2 샷 고치기 두 묶음: 시작(지문 · 인물과 모습 · 배경 · 대사 · 크기 · 앵글 → 연출도 다시) / 연출(무브먼트 · 방향·액션 · 길이, 옵션 또는 그리기 → 연출만 다시). 끝 그림은 없다. 다시 그린 러프는 카드에 "적용 전" → [되돌리기] [적용]
- S4 샷 추가(같은 팝업, Artist 목록에서만 · 없으면 R3 롤백) · S8 씬 추가 · S5 모습 추가(샷 편집의 모습 ▾ → Artist 상세 팝업) · ⋯ 앞으로/뒤로/복제/삭제
- SG 채팅 요청 → 바뀐 샷 노랗게 → [적용] [되돌리기]
- SM 마스터 시트 · S7 Director로(러프 없는 샷은 빠짐 · [남은 컷 그리기])
- v18에서 뺀 것: 인물·배경 서랍과 정보 채우기(Artist에서 끝남), 산문에 없는 인물 추가(롤백으로), 인물 강조 보기, 여러 샷 선택

## 빠진 인물 · 산문 재점검 (Artist, A1c → WT)

기본 목록 화면(A1)에는 점검 안내를 띄우지 않는다. 목록을 보던 사용자가 이상함을 느껴 [인물·배경이 빠졌거나 겹쳤어요]를 누를 때만, 바로 롤백하지 않고 먼저 묻는다(A1c): **산문을 다시 쓸래요? 아니면 산문을 재점검할까요?**

- **산문 재점검** → 목록 위에 산문이 팝업으로 열린다(WT). 산문은 잠긴 채로, AI가 뽑은 것만 인물(파랑)·장소(초록)로 표시돼 있다. AI가 모른 말에 "확인 필요" 같은 추측 표시는 하지 않는다.
  - 빠진 말(경비 아저씨): 산문에서 드래그해 고름 → [＋ 추가하기] → [인물로 추가] / [장소로 추가]
  - 틀린 이름(틴장): 목록이나 산문의 표시를 눌러 [수정] → 이름을 고친다. 이미 있는 이름(팀장)으로 고치면 "틴장 → 팀장, 하나로 합칠까요?"를 묻고(WTm) 합친다. 틴장은 팀장의 다른 이름(또는)으로 남는다. 수정 중에 [목록에서 빼기]도 할 수 있다.
  - [목록에 반영]하면 Artist 목록이 표시대로 다시 채워진다. [취소]하면 고친 표시를 되돌린다.
- **산문 다시 쓰기** → 롤백(R1). 산문에 없는 인물·배경을 넣을 때.
- 그림을 만든 뒤(A5)에도 [인물·배경이 빠졌거나 겹쳤어요]로 같은 질문을 한다. 재점검은 스타일과 지금 그림을 그대로 두고 목록만 고친다. 새로 넣은 객체는 [목록에 반영]하면 지금 스타일로 자동 생성된다. 합칠 때는 [팀장 그림] / [틴장 그림] 중 어느 그림으로 할지 고르고, 고르지 않은 그림은 기록(시계 아이콘)에 남는다. 다시 쓰기는 R2(그림 있음 롤백).
- 열린 질문: 합칠 때 산문의 표기(오타)까지 고칠지 · 자동 생성되는 새 객체의 크레딧 안내 위치.

## 1안 / 2안 (Producer · Writer)

Producer와 Writer만 두 안으로 나눠 비교한다. 두 페이지 위쪽의 전환 버튼으로 바꾼다. Artist · Storyboard · Director는 두 안이 같다.

- **1안 · 화면에서 고르기** — Producer는 두 화면(① 이야기 재료 ② 추천이 미리 골라진 설정). Writer는 산문 위 한 줄: 지금 산문이 쓰인 조건(글) + [직접 작성] + [AI 다시 쓰기 ▾]. 다시 쓰기 버튼 아래로 러닝타임 · 장르·분위기 · 소재 옵션이 펼쳐지고 [이 조건으로 다시 쓰기]로만 적용된다. 그래서 조건과 산문이 어긋난 채 브레이크다운하는 일이 없다. 채팅은 옆에서 자유 요청.
- **2안 · 채팅으로 만들기** — Producer는 에이전트가 "무엇을 만들까요?"로 먼저 묻고 [자료 올리기] [직접 적을게요] [예시 들려줘]로 시작한다. 파일을 올린 사람은 자료 종류에 맞춰 "어떻게 쓸까요"(대본이면 바로 영상화 / 조금 다듬어서 / 완전 새롭게)를 먼저 묻는다. 글만 쓴 사람은 에이전트가 장르·분위기 → 길이 → 바꿈 정도 → 화면 비율을 하나씩 묻는다(버튼 또는 말). 말에서 읽은 값은 건너뛰고, 위쪽 요약 칩으로 다시 물을 수 있다. Writer는 조건 패널 없이 채팅으로 고친다.
- 두 안 공통: 채팅에서 "다시 써줘" → "뭐가 마음에 안 드세요?" → 전부(조건 카드) / 일부분(문단 골라 그 부분만).

데이터에서는 노드·엣지의 `plan: 'A' | 'B'`로 나눈다 (`src/flow.js`).

## 바꿈 정도 (AI 개입 정도)

Producer 설정에서 고른다(1안 ② 설정, 2안 채팅 카드). 단계마다 지키는 것과 바꾸는 것을 못박는다.

| 단계 | 이름 | 지켜요 | 바꿔요 |
|---|---|---|---|
| 1 | 그대로 | 문장 · 대사 · 줄거리 · 결말 | 장면 나누기와 빠진 연출만 |
| 2 | 다듬기 | 소재 · 인물 · 줄거리 · 결말 | 문장 · 대사 · 장면 순서 |
| 3 | 새롭게 키우기 | 소재 · 장르·분위기 · 길이 | 줄거리 · 인물 · 결말에 새 아이디어 |

"그대로"는 지킬 원문(글 파일, 글이 담긴 이미지, 또는 60자 넘는 줄거리)이 있을 때만 열린다.

## Producer 입력 규칙

- 글은 최소 20자. 파일이 있으면 글은 비워도 된다. 짧으면 "조금 더 적어 주세요" 안내(⚠ E1e).
- 파일 첨부는 팝업에서. 글 파일 txt · md · docx · pdf · hwp, 글이 담긴 이미지 png · jpg, 10MB까지. 그 밖의 확장자는 팝업 안에 오류 안내(⚠ EFe).
- 이미지에서 글을 못 찾으면 읽기 실패 안내(⚠ E2e).
- 이미지 권리 동의는 없앴다. 웹툰 · 캐릭터 시트 · 참조 사진 읽기는 v2.
- AI가 글을 읽고 장르·분위기 · 길이 · 바꿈 정도 추천을 기본값으로 넣고, 이유를 한 줄로 보여준다.

## 플로우차트 그리는 방식

- Mermaid 10.9.1, 선은 직각(`stepAfter`). 11.x는 선 모양 설정을 무시해서 10.9.1을 쓴다.
- 단계마다 따로 그린다. 다른 단계로 가는 선과, 같은 단계 안에서 앞 노드로 되돌아가는 선(아니오 · 저장/취소 · 적용 후 돌아가기)은 길게 돌지 않고 `→ ID` / `↩ ID` 작은 상자로 끝난다. 상자를 누르면 그 노드로 간다.
