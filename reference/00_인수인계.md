# Tale Studio 리뉴얼(축소) 인수인계 — 2026-10-13

새 채팅에서 이 문서부터 읽고 시작하세요. 목적은 **기존 플로우가 어떻게 돌아가는지 보이고, 어디를 바꾸는지 표시하는 것**입니다. 무엇을 바꿀지는 수민이 정합니다. 아래 "오늘까지의 제안"은 참고용입니다.

---

## 1. 기존 플로우 (2026-10-12 실제 화면 + 아키텍처 지도 기준)

```
P1 기초 세팅 ─▶ P2 Producer 화면 ─▶ [Writer로 넘기기] ─▶ Writer 01~15 ─▶ Artist ─▶ Director ─▶ Editor
```

| 단계 | 화면/동작 | 정하는 값 |
|---|---|---|
| **P1 기초 세팅** | 1 자료·아이디어 → 2 쓰임새 → 3 길이·화면 → "Producer로 시작하기" | 아이디어, 파일 첨부(이미지는 권리 동의 창), 쓰임새(대본 그대로 / 다듬어서 / 아이디어·메모 — 파일 올렸을 때만), "무엇을 만들고 싶으세요?"(단편/드라마 파일럿/광고/원작 영상화/MV/직접) → 화면 비율·러닝타임 자동 채움 |
| **P2 Producer 화면** (Meeting Room) | 에이전트 채팅으로 채움. 제작 여정(이야기 씨앗 → 설정 확정 → 주인공 등장 → 무대 완성 → Writer 호출) | 설정 칩(러닝타임·장르·스타일·포맷·톤·대사 언어·채팅 언어), Casting·Background 카드, 씬 스토리(= Writer 01~04 결과), 다시 쓰기 카드(조금만 다듬기 / 표현을 새로 / 아이디어부터 다시 / 직접 입력) |
| **넘기기 게이트** | "Writer로 넘기기" → 씬 스토리 확정 | 러닝타임 일치 검사 있음 |
| **Writer 이야기 짜기** | 01 드라마투르기 · 02 서사 구조 · 03 씬 목록 · 04 이야기 점검 → 08~10 씬 촬영 설계 → 11~14 샷·대사 → 15 러프 | |
| **Writer 보이는 모습** | 05 비주얼 아이덴티티 · 06 막별 색·빛 · 07 인물·배경 디자인 | 06·07이 01~03 결과를 받아 씀 |
| **Artist** | 07 뒤 자동 시작, 인물 시트·배경 생성 | |
| **Director → Editor** | 샷 이미지·영상, 편집 | |

업로드 자료에 대한 LLM 행동(P1 진입 시)은 수민이 정리한 **"Tale Studio 유저 플로우.html" (2026.10.13 정리본)** 이 기준: 글 1-1 영상까지 고려된 대본 / 1-2 일반 대본 / 1-3 아이디어 노트, 이미지 2-1 캐릭터 시트·컨셉아트 / 2-2 웹툰 / 2-3 참조용 사진 → 의도 → 단계.

값의 영향 범위는 개발 아키텍처 지도 **02 입력 영향도**(IMPACT_NODES / IMPACT_LINKS)를 기준으로 봅니다. 04 Persona 유저 저니는 이번 축소 단계에는 쓰지 않습니다.

## 3. 오늘까지의 제안 (참고용 — 결정은 수민)

- **기초 세팅 B안**: 작업 언어·화면 비율은 잠금. 장르·톤·길이·AI 개입 정도는 산문 조건으로만, "산문 확정 · 넘기기"에서 끊김.
- **Producer는 산문만**: 조건 변경은 다시 쓰기 카드로만. 설정 칩, Casting·Background, 스타일, 대사 언어, "무엇을 만들고 싶으세요" 제거.
- **파이프라인 A안**: 확정 뒤 Artist(A0 인물·배경·스타일 + 05~07)가 먼저 보이고, Writer(01~04 → 08~10 → 11~14 → 15)는 뒤에서. Artist의 인물·배경 목록은 Writer에 목록으로만 전달.
- **스타일**: Artist에서 정하고 잠금. Artist·Director 어디서든 바꾸면 리셋.
- **장르·톤(비주얼)**: 생성 객체마다 적용(애니 스타일인데 이 인물만 호러).
- **Writer**: 총 러닝타임은 샷 길이 합 표시만. 대사 언어는 옵션, 대사마다 한/영.
- **남은 질문**: Director에서 씬마다 장르·톤을 줄 수 있게 할지.
- **개발 확인**: 06/07이 02/03 없이 돌 수 있는지 · 08/11이 05/06을 받는지 · 넘기기 러닝타임 검사 제거 · 스타일 잠금/리셋 저장 · 객체별 장르·톤 저장 · 대사별 언어 저장 · Producer 산문을 누가 쓰는지(지금은 Writer 01~04).

## 5. 새 채팅 작업 방식

- **코드로 진행**: 플로우차트(데이터) → 프로토타입 순서. 둘이 같은 노드 ID를 쓰게 해서, 플로우차트에서 노드를 누르면 프로토 해당 화면이 열리게.
- **첫 산출물 제안**: "기존 플로우 지도" 한 장 — 노드마다 상태 표시(유지 / 바꿈 / 삭제 / 오류)를 비워 두고 수민이 직접 고르게.
- **Figma는 UI 단계에서만** (Figma MCP 연결됨).
- **크레딧 절약**: 파일은 작게 쪼개기, 요청은 묶어서, 스크린샷은 필요할 때만, 이 문서로 맥락 전달(이전 대화 전체를 다시 읽지 않기).
- Tale Studio 실제 화면 확인은 가능하되, 프로젝트 생성·동의 창 수락·유료 생성은 하지 않음.
