# Tale Studio 1차 오류 리포트

**대상:** Tale Studio (talestudio.art)
**테스트 범위:** Producer → Writer → Artist → Director 전 구간
**테스트 프로젝트:** "만수의 아침" (8샷 코미디 대본, 내레이션 포함)

---

## 1. 에러 처리

### 1-1. 내레이션 사용에 필요한 절차가 안내되지 않음

**현상**

대본에 내레이션을 포함해도 그대로 반영되지 않는다. 내레이션을 사용하려면 다음 절차가 필요하다.

1. 에이전트에 "내레이터를 임의로 추가해줘"라고 요청해 내레이터를 캐릭터로 생성
2. 생성된 내레이터의 외형을 제거하고 목소리만 등장하도록 설정

이 절차는 화면 어디에도 안내되어 있지 않다.

**영향**

내레이션은 영상 문법의 기본 요소다. 절차를 모르는 사용자는 내레이션을 사용할 수 없다.

**기대**

대본에서 내레이션이 감지되면 "내레이터를 캐스팅에 추가할까요?" 안내와 원클릭 액션을 제공.

---

## 2. 상태 동기화

### 2-1. 채팅으로 확정한 설정이 반영되지 않음 (간헐적)

**재현**

Producer에서 대사 언어를 채팅으로 지정 → 에이전트가 "확정할게요" 응답 → 칩 상태 확인

**현상**

채팅에서 3회 확답하고 에이전트도 3회 확정 응답했으나 칩은 "대사 언어 비어 있음" 상태를 유지했다. 칩을 직접 클릭해 드롭다운(한국어/English/日本語/中文)에서 선택해야만 반영된다.

Producer 패널에서도 동일하다. 패널에서 슬롯을 수정해도 적용되지 않으며, 에이전트와 동시 조작이 불가능하다.

**발생 조건**

상시 발생이 아닌 간헐적 발생. 이전 작업에서는 정상 반영된 사례가 있어 재현 조건을 특정하지 못했다.

**기대**

패널에 "적용하기" 버튼을 추가해 반영 시점을 명시. 채팅 확정과 패널 수정의 우선순위 정의.

---

## 3. 컨트롤 발견성

### 3-1. 개별 샷 생성 기능이 호버 상태에서만 노출됨

**현상**

개별 샷 생성 기능은 두 경로에 존재한다.

- 스토리보드 뷰: 샷 카드 호버 시 나타나는 메뉴의 "이미지 재생성"
- 노드 뷰: 노드 이미지 클릭 → 좌측 편집 패널 하단 버튼

두 경로 모두 상시 노출되지 않아 기능의 존재를 인지할 수 없다. 상단의 "스토리보드 생성 N/M"만 보이므로 전체 배치 생성만 가능한 것으로 인식된다.

**기대**

샷 카드에 상시 노출되는 액션 버튼 배치.

### 3-2. 에이전트 안내문과 실제 구현 불일치

**재현**

Director 에이전트가 "샷 카드를 선택하면 위에 이미지 생성 버튼이 떠요"라고 안내 → 샷 카드 선택

**현상**

안내한 버튼이 나타나지 않는다.

**기대**

안내문을 실제 구현에 맞게 수정하거나, 구현을 안내문에 맞게 추가.

### 3-3. 노드 뷰와 스토리보드 뷰의 편집 UI가 상이함

**현상**

동일한 샷에 대해 진입 경로별로 다른 편집 UI가 열린다.

- 노드 뷰: 이미지 클릭 → 좌측 편집 패널 (프롬프트, 모델, 캐스트 설정)
- 스토리보드 뷰: 카드 더블클릭 → 펜 툴 편집창 (시작/연출/끝 3프레임 드로잉)

**확인 요청**

의도된 역할 분리인지 확인 필요. 의도라면 구분이 화면에 드러나야 하고, 아니라면 통합 대상이다.

---

## 4. 버튼 활성화 / 게이팅

### 4-1. 노드 뷰 편집 패널의 "이미지 생성" 버튼이 클릭 후 무반응

**재현**

Director → 노드 뷰 → 샷 노드의 **이미지 클릭** → 좌측 편집 패널 열림 → 패널 하단 "이미지 생성" 클릭

**현상**

버튼 상태와 화면 모두 변화가 없다. 작업은 에이전트 쪽에서 실제로 진행되고 있으나, 사용자는 미반응으로 인식해 반복 클릭하게 된다.

**참조 구현**

동일 기능이 스토리보드 뷰에는 정상 구현되어 있다. 비용 확인 모달을 표시하고, 실행 후 카드에 스피너와 "이미지 생성 중" 라벨을 노출한다. 노드 뷰 편집 패널에만 두 가지가 모두 누락되어 있다.

**기대**

클릭 즉시 로딩 상태 전환 및 비활성화 처리로 중복 클릭 차단.

**추가 확인 필요**

중복 클릭이 중복 생성 요청으로 전달되어 Takes가 이중 차감되는지 확인.

### 4-2. 직접 입력 칸에서 타이핑으로 버튼이 활성화되지 않음

**재현**

Producer 직접 입력 칸에 값 입력 → 제출 버튼 상태 확인

**현상**

값을 입력해도 제출 버튼이 활성화되지 않는다. 엔터 입력 시에는 정상 동작한다.

**영향**

비활성 버튼은 "입력이 아직 부족하다"는 신호로 읽히므로, 사용자는 엔터를 시도하지 않고 진행이 막힌다.

**기대**

입력값 변경 시점에 버튼 활성화 상태 갱신.

---

## 7. 생성 품질 / 일관성

### 7-1. 파이프라인 통과 과정에서 사용자 입력 대사가 소실됨

**현상**

처리 흐름은 다음과 같다.

대본 입력 → 트리트먼트(산문) 변환 → 씬·샷 분할 → **대사 AI 재생성**

이 과정에서 원본 대본의 대사가 보존되지 않고 전부 새로 생성된 대사로 교체된다.

**영향**

사용자가 직접 작성한 대사는 가장 먼저 확정되는 입력값이나, 파이프라인 중간 단계에서 소실된다.

**기대**

원본 대사 보존. 재생성이 필요한 경우 사용자 확인 절차 추가.

---

## 개발 / 기획 문의 사항

1. 사용자가 입력한 대사를 보존하는 옵션이 있습니까? 없다면 추가 가능합니까? 관련해서, Writer의 "샷 추가" 기능에서 대사도 함께 추가할 수 있습니까? 현재 샷 추가에는 대사 입력란이 없어, 대사 추가·수정은 에이전트 채팅으로만 가능합니다. (7-1 관련)

2. 무엇을 위해 트리트먼트가 있는 것인지 설명 부탁드립니다. 현재 읽기 전용이라 사용자가 수행할 수 있는 동작이 없습니다.

3. Director 노드 뷰와 스토리보드 뷰의 편집 UI가 다른 이유는 무엇입니까? (3-3 관련)

4. Producer 단계에서 레퍼런스 이미지를 등록할 수 있습니까? 캐릭터뿐 아니라 배경 등 참조가 필요한 요소 전반에 해당합니다. 현재는 AI가 전체를 생성한 후, 수정 단계(Artist·Director)에서만 레퍼런스를 투입할 수 있습니다. 이 순서로 설계한 이유를 확인하고 싶습니다.

5. 현재 파이프라인은 글(스토리·대사·연출)이 확정되기 전에 시각 산출물이 먼저 생성됩니다. 이후 글을 수정하면 이미 생성된 이미지가 무효화되고 재생성 비용이 발생하며, 이 되돌림이 반복됩니다. Writer 재실행 확인 모달에도 "downstream 산출물이 orphan/stale 될 수 있어요"라고 안내되어 있어, 팀 내에서도 인지하고 있는 사안으로 보입니다.

   이 순서가 의도된 설계인지 확인하고 싶습니다. 답변에 따라 개선 방향이 달라집니다.

   - **의도된 설계인 경우** (시각 결과를 빠르게 확인시키는 것이 제품의 강점): 되돌림 비용을 줄이는 방향이 과제가 됩니다. 수정 시 무효화되는 범위와 재생성 비용을 사전에 표시하고, 전체 재실행 대신 부분 재생성을 지원하는 방식입니다.
   - **의도된 설계가 아닌 경우**: 앞단(Producer·Writer)에서 시각화로 넘어가기 전에 확인 절차를 강화해, 글의 완성도를 먼저 확보한 뒤 생성으로 넘기는 방향이 가능합니다.

   후자의 방향이 초기 기획의도와 상충되는지 확인 부탁드립니다.
